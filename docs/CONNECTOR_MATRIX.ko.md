# MORI 커넥터 호환성 매트릭스 (R5)

MORI 가 붙일 수 있는 소스와 **성숙도·연결 방식·인증·필요 설정·상태**를 한눈에.
정직 원칙: 실제 라이브 API 로 검증된 것만 `실검증`, 고객이 밀어넣는(push) 수신형은
`부분`, 미검증 스캐폴드는 `준비중`으로 표기한다(부풀리지 않음).

| 커넥터 | 방식 | 성숙도 | 인증 | 필요 설정(env) | 연결 테스트 | 상태 |
|--------|------|--------|------|----------------|:----:|------|
| **Zabbix**(서버 경보) | pull | 실검증 | API 토큰 **또는** 사용자/비번 | `MORI_ENABLE_ZABBIX` · `MORI_ZABBIX_API_URL` · `MORI_ZABBIX_API_TOKEN`(또는 `MORI_ZABBIX_USER`+`MORI_ZABBIX_PASSWORD`) | ✔ [연결 테스트] | 사용 가능 |
| **Fleet**(PC/노트북) | pull | 실검증 | API 토큰 | `MORI_ENABLE_FLEET` · `MORI_FLEET_API_URL` · `MORI_FLEET_API_TOKEN` | ✔ [연결 테스트] | 사용 가능 |
| **Trivy**(취약점) | push | 부분(수신형) | 인제스트 토큰(선택) | (서버측 없음) · 고객 CI 가 `POST /ingest/trivy` | — 수신 대기 | 사용 가능 |
| **코드 보안 리뷰** | push | 부분(수신형) | **GitHub OIDC 서명**(권장) 또는 인제스트 토큰 | (서버측 없음) · 워크플로가 `POST /ingest/code-review` | — 수신 대기 | 사용 가능 |
| **Wazuh**(보안 경보) | push | 준비중(미검증) | 인제스트 토큰(선택) | `MORI_ENABLE_WAZUH` · 고객 integrator 가 `POST /ingest/wazuh` | — 수신 대기 | 스캐폴드 |

## 방식·용어

- **pull**: MORI 가 주기적으로 소스 API 를 호출해 수집. `[연결 테스트]`(온보딩 카드)로 즉시 검증 가능.
- **push**: 고객 CI·에이전트·integrator 가 결과를 MORI 로 전송. MORI 는 코드를 저장하지 않고 결과만 수신.
- **성숙도**: 실검증(라이브 API 검증) · 부분(수신형, 스키마 안정) · 준비중(스캐폴드, 미검증).
- **인제스트 토큰**: `MORI_INGEST_TOKEN` 설정 시 push 에 `Authorization: Bearer`/`X-MORI-Token` 필요. OIDC(코드리뷰)는 서명으로 provenance 를 위조 불가하게 검증.

## 온보딩에서 보는 법

`/admin` 첫 화면 **온보딩 카드 → 커넥터 연결 상태**에서 각 커넥터의 성숙도 배지·연결 상태·
[연결 테스트](pull 만)·미설정 env 를 실시간으로 확인합니다. 이 매트릭스는 그 정적 요약본입니다.

## 보류 중(별도 보안 에픽) — 연결 마법사 시크릿 UI

현재 pull 커넥터 자격증명은 **서버 env** 로만 설정합니다(온보딩 [연결 테스트]는 그 env 값을
그대로 검증 — SSRF 없음). **UI 에서 시크릿을 직접 입력받아 저장**하는 "연결 마법사"는
암호화 저장·키 관리·권한 설계가 필요한 보안 과제라, 급히 넣지 않고 별도 에픽으로 둡니다
(모리다움: 보안 코어는 서두르지 않음). 착수 시: 저장소 암호화(at-rest)·키 회전·감사 로그·
admin 전용 쓰기 게이트를 함께 설계.
