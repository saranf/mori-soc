> ## 이 제품의 중심
> **"이미 쓰고 있는 보안·모니터링 도구가 만드는 데이터를,
> 인증 심사 때 그대로 낼 수 있는 '증적'으로 자동으로 바꿔 주는 프로그램."**
>
> 새 도구를 도입하는 게 아니라, **기존 도구 위에 읽기 전용으로 얹혀** 증적을 쌓습니다.
> 대상 인증: **ISMS-P · ISO 27001**.

---

## 30초 요약 — 무엇이 바뀌나

| | MORI 없이 (현재) | MORI 있으면 |
|---|---|---|
| 증적 모으기 | 담당자가 엑셀·스크린샷으로 수작업 | 도구 데이터에서 **자동 누적** |
| 경보 종결 근거 | 기억·메신저에 흩어짐 | **누가·언제·왜**를 클릭 한 번에 기록 |
| 개인정보 흐름도 | 매년 손으로 다시 그림 | 코드 스캔으로 **자동 초안 + 감사관용 PDF** |
| 감사 제출 | 폴더 뒤져 짜깁기 | 통제별 증적 **PDF·CSV·ZIP(위변조 서명)** 한 번에 |

한 줄로: **"보안을 잘하는 것"이 아니라 "잘한다는 걸 증명하는 서류"를 자동화**합니다.

---

## 왜 이게 문제인가 (이해 안 가면 이 부분만 읽으세요)

ISMS-P, ISO 27001 같은 보안 인증을 준비해 보면 진짜 힘든 건 이겁니다.

- 우리 회사가 보안을 **안 하는 게 아니라**, "하고 있다는 걸 서류로 증명"하는 데 시간이 다 갑니다.
- 심사관은 묻습니다 — *"이 경보 왜 닫았어요? 누가 승인했어요? 개인정보 어디에 저장돼요? 작년 거랑 뭐가 바뀌었어요?"*
- 이걸 보안 담당 **1~2명**이 엑셀과 캡처로 손수 정리합니다. 매년 반복됩니다.

MORI는 이 **"증명 서류(증적) 모으기"** 를 자동화합니다. 그게 전부이자 핵심입니다.

## MORI의 대표 기능 — 개인정보 처리흐름 자동화

여러 기능이 있지만, **가장 손이 많이 가던 일**을 MORI가 어떻게 바꾸는지 하나만 자세히 보여드립니다.

**기존:** 개인정보가 우리 시스템 어디에 어떻게 흐르는지(수집→저장→이용→파기)를
담당자가 개발자에게 물어 가며 매년 손으로 그림.

**MORI:**
1. 고객 저장소의 코드를 **스캔**(무료 규칙 기반 또는 유료 AI)합니다. — *MORI는 코드를 가져오지 않습니다.*
2. 스캔 결과에서 **개인정보 항목**(이메일·주민번호·카드번호…)과 **저장 위치(DB 테이블·컬럼)**를 뽑아
3. **정보주체(고객) → 수집 → 저장 → 이용 → 파기** 로 이어지는 **처리흐름도**를 자동으로 그리고
4. 감사관에게 낼 **PDF**로 내보냅니다. (어느 컬럼에 어떤 개인정보가 있는지 매칭 표 포함)

## 이것도 됩니다 (한눈에)

| 기능 | 무엇을 |
|---|---|
| **통합 대시보드** | 자산·경보·취약점·오늘 할 일이 한 화면에 |
| **경보 처리(Triage)** | 접수→조사→완료 + 원본 도구로 딥링크, 처리 이력 자동 |
| **취약점·위험성 평가** | CVE별 3×3 매트릭스 → 점수(1~9) + 조치·예외 관리 |
| **통제 카탈로그** | ISMS-P 101 + ISO 27001 93 = 194 통제(한/영) 이행상태·증적 연결 |
| **증적 무결성** | 출처를 GitHub 서명으로 검증 + 내보낸 ZIP에 위변조 방지 서명 |
| **계정 거버넌스** | 서버·PC 계정 × 승인대장 대조 → 퇴사자·미승인 권한 탐지 |
| **역할별 화면 / 한·영** | 담당 범위만 보이게, 전 화면 한/영 즉시 전환 |

> 자세한 기능별 설명은 **[상세 기능 소개서](FEATURE_GUIDE.ko.md)** 참고.

## 무료 vs 유료

- **무료(기본):** 규칙 기반 스캔(Semgrep) + 모든 증적 관리·PDF·통제 기능. **결과가 항상 동일**(감사 재현성).
- **유료(선택):** AI(Claude) 심층 리뷰 — 코드 로직·개인정보 맥락까지. 정확도↑, 대신 결과가 판단형(소폭 변동).

감사 제출용으로 **재현성이 필요하면 무료(규칙 기반)** 를, 더 깊은 분석이 필요하면 유료를 씁니다.

## 누구를 위한 건가

- 보안 담당 **1~2명 + IT 헬프데스크**로 ISMS-P·ISO 27001을 준비하는 **중소 조직**
- 이미 **Zabbix 등 오픈소스 도구를 쓰고 있고** 그 데이터를 인증 증적으로 바꾸고 싶은 팀
- 컨설팅 없이 **스스로(셀프 호스트)** 증적을 쌓고 싶은 팀

## 정직하게 말하면 (이게 MORI의 성격입니다)

- **알파 단계**입니다. 일상 보안 운영 + 감사 증적 시나리오는 동작하고, 상태는 DB에 저장됩니다.
- **Zabbix 연동은 실제 API로 검증**됐고, 다른 커넥터는 순차 확장 중입니다.
- **AI 결과는 후보**이며 사람 검토가 필요합니다. 개인정보 판단은 법적 확정이 아닙니다.
- 통제 194개 중 **검토완료 58개는 그대로 "58개"** 라고 씁니다(부풀리지 않음).

> 무엇이 자동 사실이고 무엇이 AI 후보이며 무엇이 사람 판단인지 **구분해서 보여주는 것** —
> 그게 증적 제품의 기본이라고 생각합니다.

## 자주 묻는 질문

**Q. 우리 코드를 MORI가 가져가나요?**
A. 아니요. 스캔은 **고객의 CI(예: GitHub Actions)에서** 돌고, MORI는 **결과만** 받습니다.

**Q. 기존 Zabbix/Grafana를 버려야 하나요?**
A. 아니요. MORI는 그 위에 **읽기 전용**으로 얹힙니다. 시각화는 Grafana가, 증적은 MORI가.

**Q. 인증을 대신 통과시켜 주나요?**
A. 아니요. MORI는 **증적을 모아 주는 도구**입니다. 최종 판단·승인은 사람이 합니다.
