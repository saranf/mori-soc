# MORI SOC — 1인 보안담당자 ISMS-P / ISO 27001 준비 관점 기능 갭 분석

> **시나리오** — 보안담당자 **1명**이 이 포트폴리오(MORI SOC)만으로 **ISMS-P(국내) / ISO 27001(해외)** 인증을 혼자 준비한다.
> **질문** — 실제 법령·고시·표준 요구사항에 비추어 **① 기존 기능 중 무엇을 어떻게 보강**하고 **② 어떤 기능을 추가**하면 좋은가.
> **방법** — 인증기준 영역별로 (법적근거 → MORI 현재 구현 → 갭 → 권고) 를 매칭하고, 1인 준비자 기준 레버리지 순으로 정렬.
> **작성일** — 2026-07-11 (rev.2 — 접속기록 모듈 부분 구현 반영)

## 0. 결론 3줄

1. MORI의 강점은 **기술·운영 통제의 자동 증적**(취약점·자산·계정·사고·위험평가)이고, 이는 인증기준의 **~25% 상한**을 스스로 정직하게 명시하고 있음 — 이 상한 안에서 비어 있던 **접속기록 관리(안전조치 제8조)** 는 이번에 보존현황 지표·월간 점검 워크플로·Loki 라이브 클라이언트로 **부분 구현**됨(rev.2). 남은 최고 레버리지는 아래 §4로 이동.
2. ISMS-P의 **P(개인정보 처리단계별 21개 기준)**·**관리체계 점검(내부감사·경영진검토)**·**SoA(ISO 필수산출물)** 는 1인 준비자에게 실사 부담이 가장 큰데 MORI에 **거의 부재** — 문서 GRC로 전면 확장하기보다 **경량 스캐폴딩**(대장·워크플로·자동생성)으로 "한 화면"을 완성해야 함.
3. 카탈로그는 194개 전부 열거됐으나 **58개만 reviewed(29.9%)** — 1인 준비자에게 "194개 준비됨"으로 오독될 위험이 실사 리스크. **review 스프린트 도구**로 draft를 빠르게 승격하는 것이 자동 증적 확대만큼 중요.

## 5. 제품 전략 코멘트 (범위 규율상 제안만)

- MORI의 정체성은 **"증적 층"**이지 문서 GRC가 아니다. 3.x·1.4·2.2~2.4 같은 **문서영역**을 무겁게 자체구현하면 정체성이 흐려지고 Vanta/Drata와 정면충돌한다 → **경량 대장·워크플로 + 증적 슬롯**으로만 "한 화면"을 완성하고, 본문 문서는 외부 링크·첨부로 위임하는 것이 정합적.
- 반대로 **접속기록·암호화·재해복구·개발보안**은 MORI의 자동증적 해자를 **법정 강행기준(안전조치 제7·8·11조)** 위에서 넓히는 방향이라 최우선 투자 가치가 있다.
- **SoA + 내부감사**는 "판단→기록→증명" 서사를 관리체계 상단까지 완성시키는 **적은 노력·필수 산출물** — 로드맵 Phase 4에서 앞당길 후보.
